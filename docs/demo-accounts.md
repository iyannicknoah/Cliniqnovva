## Running the seed script

```bash
cd backend
node scripts/seedDemoData.js
```

Targets whatever Firebase project `backend/.env.<NODE_ENV>` points to
(default `NODE_ENV=development` → the `cliniqnovva-dev` project per
`firebase/.firebaserc`) — **never run this against `cliniqnovva-prod`**.
Not idempotent: Firebase Auth rejects a second run's duplicate emails
loudly (`auth/email-already-exists`), but re-seed by using a fresh/reset
project rather than running it twice against the same one.

## Verifying zero emails/invites

`backend/package.json` has no email or SMS dependency at all (no
nodemailer, SendGrid, Twilio, AWS SES, etc. — confirmed during the Part 18
security review, `docs/security-review.md`). Account creation calling
`auth.createUser()` + `auth.setCustomUserClaims()` directly, with the
account active from the first write, is structurally incapable of sending
anything — there is no code path that could.
